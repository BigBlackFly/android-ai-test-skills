# App UI/UX知识库

## 用途与入口

用于让UI测试Agent发现相关App资料，按页面理解布局、功能位置和交互逻辑。

| App ID | 名称 | 候选检索词 | 包名 | 资料入口 | 覆盖 |
|---|---|---|---|---|---|
| gallery | 图库 | 相册、Gallery、照片管理 | com.zui.gallery（项目指定） | [图库App](apps/com.zui.gallery/README.md) | 19份设计来源，15个页面/局部页面主题、4个跨页面主题 |
| settings | 系统设置 | 设置、Settings、系统设置 | com.zui.settings（项目指定） | [系统设置App](apps/com.zui.settings/README.md) | 41份设计来源，42个页面/页面组、5个跨页面主题 |

## Agent加载规则

本库在测试期间保持只读，索引、正文、图片及原稿由知识库维护者维护。新获得的测试经验写入`knowledge/<包名>.md`，资料缺口和设计差异写入报告。

测试前先读取本库可用的相关 UIUX 内容，再读取本项目知识卡；缺少待测 App 目录或相关资料时，采用已有知识卡与设备证据继续执行测试。图库按 `com.zui.gallery`、系统设置按 `com.zui.settings` 映射；运行时仍核对设备上的实际包名和版本。

1. 根据任务识别涉及App，优先匹配已确认包名；通用别名仅用于候选发现。
2. 进入App索引，按功能找到页面资料；跨App任务分别读取相关App资料。
3. 先加载当前页面、目标功能页面和必要中间页，再按执行状态增量加载。
4. 图标或位置不清时，按当前Markdown所在目录解析局部图片相对路径，用图像能力打开。读Markdown文本不等于已读取图片。
5. 功能跨页面时读取对应主题或导航，配图按当前步骤需要加载。
6. 资料未明确/版本不适用时记录缺口；实际界面与设计冲突时记录差异，不强行按设计坐标操作。
7. 执行中对入口、交互或预期不确定，或上下文遗忘时，重新检索相关 UIUX 正文与本项目知识卡，结合用例要求和当前设备证据判断；仍不确定时暂停相关操作并询问用户。完整流程见 [使用说明](../docs/UIUX知识库.md)。

## 组织规则

- App索引：apps/<包名>/README.md，目录名与Android包名一致；App ID用于稳定知识标识，不作为目录名。
- 页面：pages/<page_id>/README.md，图片在同级images下；页面各状态和专属弹窗归同一页面。
- 跨页面主题：features/<topic_id>/README.md，描述多个页面之间的交互关系。
- 每个App另有功能索引、导航关系、来源清单和限制说明，均为Markdown。
- 一个页面可引用多张稿，一张稿也可支持多个主题；保持稳定ID和来源映射。
- 知识库维护者新增App时更新本表，新增页面时更新该App功能和页面目录；测试 Agent 按需读取资料。

## 事实与操作边界

本文保存设计知识，删除、分享、授权、购买、卸载等操作由当前任务决定。时间、数量和照片按示例理解，包名和版本以设备信息为准。支持、待上线、历史和占位设计分别标注。图片红点、连线和版本标记属于设计批注。

解压整个目录后从本文件开始读取，保留相对目录结构。
