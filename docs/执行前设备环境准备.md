# 执行前设备环境准备

每个新独立用例正式执行前读取本页。应用数据、权限、设备文件和业务前提的准备规则统一在这里维护；后续新增功能例外也在此补充。

为了增加测试过程的稳定性，更聚焦测试的重点，Agent 可以提前做一些准备工作。这些工作只允许在正式开始执行测试用例的步骤之前完成。

## 文档职责与准备顺序

本页维护设备环境准备的理由、规则和执行方法。测试主流程由 [SKILL](../SKILL.md) 组织；进入本阶段时，使用主流程已建立的当前会话，准备操作和结果沿用该会话的记录机制。

1. 根据当前用例及已查阅的资料，明确所需的环境前提，沿用当前测试的目标设备和包名。
2. 按下文选择设备文件准备方式，再分别处理 App 数据清理和授权，随后建立其他业务前提。
3. 核对准备后的状态是否满足用例前提。

## 设备文件与素材

按当前用例选择以下一种方式，由测试 Agent 显式调用：

| 用例要求 | 操作 |
|---|---|
| 要求空文件环境 | 调用 `prepare sdcard clear`，清理用户文件并刷新媒体索引，不预置素材 |
| 其他情况（默认） | 调用 `prepare sdcard init`，清理用户文件、预置测试图片和视频，再刷新媒体索引 |

命令前缀沿用 SKILL 约定；`prepare` 是 `tools/prepare/` 的目录入口。`--serial` 必须显式指定，并与当前会话的设备一致：

```powershell
# 默认准备
python prepare --serial <serial> sdcard init

# 用例要求空文件环境时，改用此命令
python prepare --serial <serial> sdcard clear
```

`init` 已包含清理，不要先 `clear` 再 `init`。两者都保留 `/sdcard/Android` 及其内容；标准媒体目录保留目录壳。清理不保证系统不会立即重建缓存，应核对用例关心的文件状态。

**文件准备不修改 App 数据和权限**，与下面的 App 清理策略分别判断。日历中的课程表用例即使保留 App 数据，仍按本节选择文件准备方式。

素材文件名和设备目标路径以 [内置测试媒体](../media-resources/README.md) 为准。用例另需素材时，在文件清理后补充，并确认媒体索引可发现它，再进入选择器。

文件准备结果以 `preparation` 事件记入当前会话。检查命令返回的 `ok` 和 `steps`；失败时查看 `error`。`INFO` 是记录级别，不代表成功；准备失败不自动结束会话，应核对实际前提，无法满足时按 `BLOCKED` 收尾。

## 清理 App 数据

App 中上次测试产生的残留可能干扰下个用例的执行，还可能被误当作经验写入知识卡。因此，一般来说，开始测试每个新的独立用例之前，应该清理目标 App 数据。

但是，日历 App 中新建课程表可能很麻烦。为了避免这部分用例媒体都要重复建课程表，课程表功能优先复用符合前提的既有数据；用例明确要求首次进入、无数据或清理时，仍必须清理。

每个新独立用例按以下优先级判断，命中一项后即确定清理策略：

| 优先级 | 条件                                             | 操作                              |
|-----|------------------------------------------------|---------------------------------|
| 1   | 不知道具体包名                                        | **跳过清理**                        |
| 2   | 用例要求“首次进入”“首次启动”“无数据”，或明确要求清理数据                | **必须清理目标 App 数据，日历中的课程表用例也不例外** |
| 3   | 日历 App（`com.zui.calendar`）中的课程表功能用例，且未命中上述清理要求 | **不清理**，保留现有课表，避免重复建数据          |
| 4   | 其他用例                                           | **一律清理目标 App 数据**               |

上述保留数据的例外仅适用于日历 App（`com.zui.calendar`）中的课程表功能。该功能的用例需要清理时，清理目标是整个日历 App 的数据。保留数据时，先检查现有课表能否满足用例；满足则复用，不足则补建。用例要求首次启动或无数据时，必须按第 1 条清理，不能用删除部分课表代替。

需要清理时调用（命令前缀沿用 SKILL 约定）：

```powershell
python state.py --serial <serial> clear --package <package>
```

## App 授权

对于一般的功能测试用例，提前给 App 授权可以避免权限弹窗干扰后续操作，让测试过程聚焦于用例要求的具体功能。

但是，如果用例本身要测试权限弹窗，那么提前授权会导致跳过待测流程，因此必须保留权限弹窗的触发条件，禁止提前授权。

授权与是否清理数据**分别判断**。先完成上面的数据处理，再按以下规则准备权限：

| 条件 | 操作 |
|---|---|
| 用例要求测试权限弹窗 | **禁止提前授权**；按用例确保待测权限尚未授予，保留权限弹窗的触发条件 |
| 用例不要求测试权限弹窗 | **提前授予 App 申请的全部运行时权限** |

“首次进入”“首次启动”本身不构成禁止提前授权的条件：用例若不测试权限弹窗，清理后仍需提前授权。日历中的课程表用例保留数据时也按本节判断；若要测试权限弹窗且相关权限已经授予，先定向撤销相关权限。

```powershell
# 不测试权限弹窗：提前授权
python prepare --serial <serial> grant-all --package <package>

# 测试权限弹窗：按用例撤销已授予的待测权限，以下以相机为例
python state.py --serial <serial> revoke --package <package> --perm camera
```

批量授权结果同样以 `preparation` 事件记入当前会话，检查返回的 `ok`、`output` 和 `exit_code`；连接或执行异常见 `error`。

## 准备结果核对

文件准备、App 清理和授权命令的结果自动记入当前会话。检查各命令返回的 `ok`、`steps`、`output` 等实际结果，再判断前提是否满足；完整参数见 [环境与工具参数](环境与工具参数.md)。

无法确定具体包名时，跳过 App 清理和预授权，记录原因，继续按用例执行。

## 其他前提与操作起点

- 用例要求“已有录音”“已拍摄照片”“没有视频”等状态时，在文件和 App 准备后操作设备建立这些条件。不能仅因初始条件不满足就放弃执行。
- 需要已有备份等数据的用例，先完成清理判断，再建立所需前提，避免准备顺序破坏刚建立的数据。
- 根据 activity 和当前屏幕锚点对照路径图定位。准备完成且已经处于目标状态时，直接开始正式步骤；否则走相关路径到达起点，无需重复返回首页。
- 无起点前提或无法识别当前页面时，可冷启动定位；冷启动使用停止/启动应用，不等于清理 App 数据。

尝试后仍无法建立必要前提，记录尝试、实际状态和未验证项，按 `BLOCKED` 收尾；遇到仍需澄清的用例要求，按 SKILL 的暂停询问流程处理。
