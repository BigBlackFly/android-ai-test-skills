# 视觉通道（vision.py）

> SKILL.md 的附录。**只在需要工具级视觉断言时读**。

## 定位

**对话内执行时，优先用你自己的判图能力**——你能直接看 `shot.png`，不需要绕一层。
`vision.py` 是给**无对话场景**（批量回放、CI 脚本）用的工具级视觉通道。

```powershell
python tools/vision.py ask --image <png> --prompt "按钮是置灰的吗？回答并给依据"
```

配置在 Web 测试台「视觉模型」页维护，Key 只存 `storage/vision.json`（不入库）。

## 什么时候才需要视觉判断

UI 树（nodes）能表达的，**一律不要用视觉**：

| 目标 | 用什么 |
|---|---|
| 界面是否打开 / 进入了哪个页面 | `activity` 字段 |
| 某个控件是否存在、文字是什么 | `--full` 的 nodes |
| toast / Canvas 自绘文字 | `read.py` OCR |
| **置灰 / 颜色 / 图标点亮 / 视觉样式** | 才需要看图或 vision |

> 视觉模型又贵又慢，且偶发调用失败会把"可见即达成"的目标误判成未达成。

## 结论口径

视觉输出是**辅助判据**，PASS/FAIL 结论仍需结合 dump / OCR 证据。

## 测试连接

Web 测试台「视觉模型」页有「测试连接」按钮，会用当前配置发一次真实请求
（1×1 PNG 最小图），验证鉴权与模型可用性，并显示耗时与错误类型提示。
