# 知识卡与链路卡

> SKILL.md 的附录。**只在要查卡、写卡、或做链路回放时读**。

## 第一原则：卡必须设备无关

我们会在**不同机型**上跑（换设备是常态）。所以卡里：

| ✗ 不写 | ✓ 要写 |
|---|---|
| 坐标、bounds、行距、列 x、屏幕尺寸 | resource-id、content-desc、文案 |
| "第 N 个箭头"、"点右下角" | activity 名、页面拓扑、导航路径 |
| `[机型/版本]` 打戳的实测数值 | 行为规律、坑、判定依据 |

**理由**：任何数值型实测值都会在下一次换机型/换方向时失效，**留着就是误导**。
需要标定时，卡里写"**怎么标定**"，不写标定结果（坐标一律 observe 拿 bounds 现场派生）。

> 真实教训：卡里记着 `TB323FU / 3040×1904`，实际设备换成 `TB522FU / 2560×3840`，
> 所有坐标类内容一次性作废。

## 第二原则：标题 = 检索键

AI 拿到的索引就是各卡的 `##` 标题（见 `_template.md` 顶部规范）。标题必须能被
**交互类型词**搜到：

```
✓  ## 弹窗-首次启动三连        ## 时间选择器-双滚轮      ## 坑-清数据会清掉备份
✗  ## 首次启动的三个弹框（实测 2026-09-11）    ← 带日期
✗  ## 全部课程表列表页（TimetableListActivity，185 实测）  ← 带用例号
✗  ## 一些踩坑记录                              ← 叙事式
```

标题里**不要带**日期、用例号、构建号。这些是易腐数据，写在正文或干脆不写。

## 两级结构

| 层 | 位置 | 内容 | 用法 |
|---|---|---|---|
| 经验层 | `knowledge/<包名>.md` | 交互类型经验、坑、弹窗策略 | 写用例/探索时查 |
| 链路层 | `knowledge/_runs/<包名>/*.md` | 一次成功会话的**可回放步骤**（定位意图 + 动作 + 检查点） | 回归同链路时查 |

另有 `knowledge/_system.md` —— 跨 App 的**系统界面**兜底卡（权限弹窗、系统对话框、
预装应用卸载/恢复等），前台包名不在任何 App 卡时读它。
`knowledge/_template.md` 是新建 App 卡的模板（含完整写卡规范）。

## 查卡

`knowledge/<前台包名>.md`，按**交互类型**词检索，**只读命中小节**，不整卡进上下文。

> `session.py start` / 首个 `observe` 会返回 **`knowledge_hint`**：卡路径 + 小节标题索引。
> 拿到就先读卡再动手 —— 卡里是跨设备实测经验，含标准链路和已踩过的坑。

标准链路命中就照走，不要从零探路。

## 写卡

- 新链路 / 新弹窗策略 / 新坑 → 更新**既有小节**，不追加带日期的段落
- **卡是地图不是日志**：一条经验一行结论 + 一行依据；过程叙事不进卡
- **过时条目直接删**，让体积收敛而非只增不减
- 空卡（只有包名没有经验）保留为极简 stub，让 AI 知道"有卡但没内容"

### 沉淀四问（写进卡之前过一遍，全过才留）

1. **换设备 / 换方向还成立吗？** 不成立就不要写（见第一原则）
2. **下次会来搜这个词吗？** 搜不到的写了白写；把词补进标题
3. **不写会做错或重探吗？** 常识/显然推论不进卡
4. **能不能下沉？** 跨 App 行为 → `_system.md`；完整链路 → `_runs/`

## 链路卡回放

链路卡命中 → 按步骤**逐条执行、每步核对返回**（不跳过观察）。

**卡里的标记**：

| 标记 | 含义 | 回放怎么做 |
|---|---|---|
| 🎯 **声明**权限意图 | 这一步**新声明**了 grant/deny | 照做（用 `--perm-action` 或先 `perm-intent`） |
| 权限意图（延续） | 沿用前面的意图 | 不用重复声明 |
| 🪟 弹窗：「标题」 | 该步动作后屏幕上的弹窗 | **据此判断当前在哪层弹窗** |
| 🔐 权限弹窗自动响应 | 权限框被自动点了哪个按钮 | 核对是否符合预期 |
| ⚙️ pm clear / pm revoke | 前置状态重置 | 必须先执行，否则分支走不到 |
| 👁 检查点 | 当时的前台 activity | 核对是否一致 |
| ⚠️ 坐标直点 | 该步没记定位意图 | **回放前必须先 observe 校准** |
| ↩️ 误操作/弯路 | 当时点错或绕行，**回放可跳过** | 跳过该步；但看一眼「理由」，弯路常含定位教训 |
| 🔍 read（OCR） | 靠 OCR 读的值（Canvas 自绘，UI 树无节点） | 见下方 OCR 步骤回放 |
| `OCR:xxx` 定位 | 该步的目标靠截图 OCR 找 | 见下方 OCR 步骤回放 |

### OCR 步骤怎么回放（`OCR:` 定位 / `🔍 read`）

这类步骤**隐含了当次截图的几何**（哪块区域、第几行、行距多少），换设备/换方向/
甚至换弹窗位置都会漂 —— **唯一可靠的是"重新 read → 重新 OCR"这个动作本身**：

1. **不要复用卡里的坐标或行号** —— 先 `read.py --image <当前截图> --region ...`
   复现一次 OCR，用**当次**结果定位
2. 找不到或漂了 → 用 `read.py` 全屏 OCR 重找目标文字，别硬套
3. ⚠️ **按次数点按，别用 OCR 结果做循环判定** —— OCR 偶发漏读会让"点一下→验一次"
   的循环原地打转（主卡 `com.zui.calendar.md` 「坑-OCR 偶发漏读」有完整记录）。
   正确做法：按**档位次数**点，点完用 **UI 树文本**做判据
4. 判据优先选 UI 树能读到的字段（rid），OCR 只用于 UI 树读不到的部分

> OCR 步骤与 `⚠️ 坐标直点` 同级：都是**机型绑定的**，回放前必须现场复现。

> ⚠️ **`rid=button1` 这类是歧义定位**：同一个 rid 在不同弹窗里是不同按钮
> （首次说明框的"同意"、提示框的"知道了"、权限框的"允许/拒绝"）。
> 回放时**必须结合 🪟 弹窗标题**确认当前是哪一层，不能盲目复用。

**任何一步失配**（元素找不到 / activity 不符）→ 回退完整 observe→决策流程，
跑通后 `session.py export` 覆盖更新链路卡。

## 双分支用例的回放

像「拍照导入」这种要同时验同意/拒绝的，链路卡里是**两轮混在一条链**：

```
🎯 deny  → 点按钮 → 验证拒绝提示 → 关提示框
⚙️ revoke（关键！）→ 🎯 grant → 点按钮 → 验证后续功能
```

回放要点：
1. **第二轮前必须有 `revoke`** —— 权限已授予时弹窗不再出现，不撤销会卡住
2. **先拒后允**的顺序不能颠倒 —— 拒绝会改变弹窗形态
3. 每轮结束用 `session.py perm-intent --clear` 清意图，避免影响下一轮

## 产出链路卡

**PASS 的会话会自动沉淀链路卡**（`finish --status PASS` 时触发），
不用手动 export —— 返回里会带 `runbook` 路径与提示。

- **失败/阻塞的会话不导出**：跑不通的链路没有回放价值，导出反而污染知识库。
  只有确实想要时才手动 `export --id <N>`。
- 不需要自动导出时加 `--no-runbook`。

```powershell
# 手动导出（一般用不到，PASS 已自动做）
python tools/session.py export --id <N>
# → knowledge/_runs/<包名>/<id>_<标题>.md
```

内容原则：
- 带 `--via` 的动作 → 记录**定位意图**（rid/text），这是缓存键，换设备可重定位
- 无 `--via` 的动作 → 只记坐标并标 ⚠️（机型绑定，回放前必须现场校准）
- 中间的 observe 摘要为检查点（断言依据），不复制节点列表
- **权限意图变化会标 🎯**、前置重置标 ⚙️ —— 双分支回放全靠这两个
- 弹窗操作会附 🪟 标题，用于消解 `rid=button1` 的歧义
- **连续重复的检查点会去重**（只去重连续；跨步骤绕一圈回到同一页仍有信息量）
- `--why` 含「误点/误操作/绕行」的步骤标 ↩️ **回放可跳过**

> 生成时若某步没有 `--via`、也没有弹窗标题，宁可标 ⚠️ 留白，
> **不要编造定位**——回放时按错定位点下去比找不到更糟。

## ⚠️ 每个预期结果都要有显式检查点

**这是跑用例时的硬约定，不是导出后能补救的。**

链路卡的用途是"可回放的规划缓存"。如果某个预期的验证只活在**结论段落**里，
回放者按步骤跑完就直接结束，**根本不会去验它** —— 跨设备回归时这正是最容易漏的断言
（往往是产品核心逻辑，比如"改一处后哪些同步、哪些不变"）。

**跑用例时的要求**：

| 口述步骤类型 | 必须留下 |
|---|---|
| "查看 / 验证 / 确认…" | **一次 `observe`**（产生 👁 检查点），或一次**带断言结论的 `read`** |
| 有明确预期值的 | 检查点要带上**判据字段**（如 `tv_lesson_duration=50分钟`），不能只记 activity |
| 前提类步骤（"进入 XX 页"） | 至少一次 activity 检查点 |

**反例（真实）**：某用例预期"后续小节同步为 53 分钟、每节课时长仍 50 分钟"，
执行时走的是 `act` 回传画面 + OCR 读值，**没有单独 observe** →
链路卡里这一条预期**零落点**，只在结论散文里出现。
回放时步骤跑完就跳结论，这个断言等于没验。

> 自检：导出后对着**用例原文的预期结果逐条数**，看每条能不能在卡里找到对应检查点。
> 找不到就补一次 observe 或补一条带判据的 finding，然后重新 export。
